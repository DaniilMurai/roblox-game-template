# Ручная проверка __DISPLAY_NAME__ в Studio

Заполняй колонку «Итог» прямо в этом файле и коммить: результаты, оставшиеся в переписке,
проверить потом невозможно.

Headless-часть (логика ядра, валидность конфига, сборка) закрыта в CI. Здесь только то,
что в терминале не проверяется принципиально: Roblox-рантайм, DataStore, ввод игрока.

## Подготовка

1. Плагин Rojo: `rojo plugin install` либо Plugins → Manage Plugins.
2. **Опубликованное место обязательно.** Без `placeId` нет доступа к DataStore,
   ProfileStore уходит в mock, и прогон выглядит успешным, ничего не сохраняя.
   File → Publish to Roblox As → Private.
3. Experience Settings → Security → **Enable Studio Access to API Services**.
   Признак готовности среды в Output:
   `[profilestore]: Roblox API services available - data will be saved`.
   Видишь `unavailable` — дальше идти бессмысленно.
4. `rojo serve` в корне тайтла, в Studio — Rojo → Connect.

## Чек-лист

Расхождение чисел в `saving` и `loaded` — баг сохранения, а не округление.

## Чего здесь нет и почему

- **Session-lock.** В Studio не воспроизводится: Test → 2 Players выдаёт клиентам разные
  UserId, ключи профилей разные, конфликту взяться неоткуда. Нужны два реальных входа
  в опубликованную игру.
- **Покупка геймпасса.** Нужен настоящий `gamepassId` на аккаунте; пока `passes` в конфиге
  пусты, проверять нечего.
- **Поведение при краше.** Stop — это чистое завершение. Ради краша и существует autosave,
  но подстроить его отсюда нельзя.

## После прогона

Откатить правку из пункта 9. Не сошедшийся пункт — это задача, а не повод идти дальше.
